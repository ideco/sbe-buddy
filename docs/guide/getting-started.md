# Getting started

This guide takes a Java record from declaration to encoded SBE message and back again.

It uses the generated record codec. The standard SBE flyweights are generated by sbe-tool alongside it and remain available when direct buffer access is the better fit.

## Add sbe-buddy

sbe-buddy requires JDK 21 or newer.

Add the API to the compile classpath:

```xml
<dependency>
    <groupId>net.concini</groupId>
    <artifactId>sbe-buddy-api</artifactId>
    <version>0.2.0</version>
</dependency>
```

Add the processor to javac's annotation processor path:

```xml
<plugin>
    <artifactId>maven-compiler-plugin</artifactId>
    <configuration>
        <annotationProcessorPaths>
            <path>
                <groupId>net.concini</groupId>
                <artifactId>sbe-buddy-processor</artifactId>
                <version>0.2.0</version>
            </path>
        </annotationProcessorPaths>
    </configuration>
</plugin>
```

Compilation requires no additional JVM flags.

Code using Agrona buffers needs:

```
--add-opens java.base/jdk.internal.misc=ALL-UNNAMED
```

## Declare a schema

An SBE schema belongs to a Java package.

Create `package-info.java`:

```java
@SbeSchema(id = 100, version = 0)
package com.example.trading;

import net.concini.sbebuddy.SbeSchema;
```

The package is the schema boundary. Messages and named SBE types declared in it contribute to the generated schema.

## Declare a message

Start with a plain record:

```java
package com.example.trading;

import net.concini.sbebuddy.SbeField;
import net.concini.sbebuddy.SbeMessage;

@SbeMessage(id = 1)
public record PlaceOrder(
        @SbeField(id = 1) long accountId,
        @SbeField(id = 2) int quantity) {}
```

The Java types determine the encoding here: `long` maps to SBE `int64`, and `int` maps to SBE `int32`.

The complete mapping is described in [Primitives](reference/primitives.md).

Wire identifiers stay explicit. The message has id 1; its fields have ids 1 and 2.

## Compile

Compile the project:

```
./mvnw compile
```

sbe-buddy generates the corresponding SBE schema and packages it as:

```
com/example/trading/schema.xml
```

It then passes that schema to sbe-tool.

sbe-tool parses the schema, builds the IR and generates the standard SBE flyweights:

```
com.example.trading.sbe.PlaceOrderEncoder
com.example.trading.sbe.PlaceOrderDecoder
```

sbe-buddy also generates:

```
com.example.trading.PlaceOrderCodec
```

## Encode and decode

Use the generated codec with an Agrona buffer:

```java
package com.example.trading;

import org.agrona.MutableDirectBuffer;
import org.agrona.concurrent.UnsafeBuffer;

public final class Example {
    public static void main(String[] args) {
        MutableDirectBuffer buffer = new UnsafeBuffer(new byte[256]);
        PlaceOrderCodec codec = new PlaceOrderCodec();

        PlaceOrder order = new PlaceOrder(42L, 100);

        int encodedLength = codec.encode(order, buffer, 0);
        PlaceOrder decoded = codec.decode(buffer, 0);

        System.out.println(encodedLength);
        System.out.println(decoded);
    }
}
```

The codec writes the normal SBE message header followed by the message body.

Decoding reads the header, checks the message identity and constructs a new `PlaceOrder`.

A codec owns its encoder and decoder flyweights and is stateful. Reuse an instance from one thread rather than sharing it between threads.

## Add richer field types

The same message can use the other field types supported by the record codec.

For example, an unsigned primitive, an enum and a set:

```java
package com.example.trading;

import static net.concini.sbebuddy.PrimitiveType.UINT16;

import java.util.Set;

import net.concini.sbebuddy.SbeField;
import net.concini.sbebuddy.SbeMessage;

@SbeMessage(id = 1)
public record PlaceOrder(
        @SbeField(id = 1) long accountId,
        @SbeField(id = 2) int quantity,
        @SbeField(id = 3, primitiveType = UINT16) int venue,
        @SbeField(id = 4) Side side,
        @SbeField(id = 5) Set<OrderFlag> flags) {}
```

`venue` uses SBE `uint16`, represented as a Java `int`. See [Primitives](reference/primitives.md) for the signed and unsigned mappings.

`side` can be declared as an SBE enum:

```java
package com.example.trading;

import static net.concini.sbebuddy.PrimitiveType.UINT8;

import net.concini.sbebuddy.SbeEnum;
import net.concini.sbebuddy.SbeEnumValue;

@SbeEnum(primitiveType = UINT8)
public enum Side {
    @SbeEnumValue("1")
    BUY,

    @SbeEnumValue("2")
    SELL
}
```

The wire values are explicit. Java ordinals are never used.

`flags` can use an SBE set:

```java
package com.example.trading;

import static net.concini.sbebuddy.PrimitiveType.UINT8;

import net.concini.sbebuddy.SbeChoice;
import net.concini.sbebuddy.SbeSet;

@SbeSet(primitiveType = UINT8)
public enum OrderFlag {
    @SbeChoice(value = 0, name = "postOnly")
    POST_ONLY,

    @SbeChoice(value = 1, name = "hidden")
    HIDDEN
}
```

Each choice names a bit position. The record represents the field as `Set<OrderFlag>`.

## Add absence and schema evolution

Fields that may be absent are represented by boxed Java types.

An optional field can be declared directly:

```java
@SbeField(id = 6, presence = OPTIONAL)
Long clientOrderId
```

A field introduced in a later schema version can also be absent when decoding an older message.

For example:

```java
@SbeSchema(id = 100, version = 2, baselineVersion = 1)
package com.example.trading;
```

```java
@SbeMessage(id = 1)
public record PlaceOrder(
        @SbeField(id = 1) long accountId,
        @SbeField(id = 2) int quantity,
        @SbeField(id = 3, primitiveType = UINT16) int venue,
        @SbeField(id = 4) Side side,
        @SbeField(id = 5) Set<OrderFlag> flags,
        @SbeField(id = 6, presence = OPTIONAL) Long clientOrderId,
        @SbeField(id = 7, sinceVersion = 2) Integer strategyId) {}
```

`clientOrderId` may be absent because it is optional.

`strategyId` may be absent because version 1 messages predate the field. When such a message is decoded, the component is `null`.

The details of absence for each field kind are covered in their reference pages.

## What was generated

The complete flow is:

```
annotated Java
      |
      v
  SBE schema
      |
      v
   sbe-tool
      |
      +--> IR
      |
      +--> standard SBE flyweights
      |
      v
 sbe-buddy codec
```

sbe-buddy starts from the Java model and generates the SBE schema.

sbe-tool parses that schema, builds the IR and generates the standard SBE flyweights.

The generated codec adds another API on top of the same schema. It lets application code work with the Java domain model where that is appropriate, while the standard flyweights remain available for code that benefits from direct buffer access and the lower-level SBE API.

The aim is not to replace the flyweights. It is to avoid forcing the rest of the application to work in terms of them.
